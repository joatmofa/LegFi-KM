LegFi KM is built for organizations that handle sensitive financial and legal information. Every layer of the platform — from the way your data is stored to the permissions model your Admins configure — is designed to protect confidentiality, ensure integrity, and maintain the audit evidence that regulated industries require. This page describes the security controls and compliance posture of LegFi KM so you can evaluate it confidently and brief your security and risk teams.

<Note>
  For vulnerability disclosures, penetration test reports, compliance documentation (SOC 2 Type II report, ISO 27001 certificate, DPAs), or any other security inquiry, contact **security@legfikm.com**. Enterprise customers may request the LegFi KM security whitepaper and detailed compliance reports under a mutual NDA.
</Note>

## Data Encryption

LegFi KM encrypts all customer data — at rest and in transit — so that your knowledge entries, version history, and audit records are protected whether they are stored on disk or moving across the network.

<CardGroup cols={2}>
  <Card title="Encryption at Rest" icon="hard-drive">
    All data stored by LegFi KM — including entry content, metadata, version history, and audit logs — is encrypted using **AES-256**. This applies to primary database storage, backup snapshots, and file attachments. Encryption keys are rotated automatically on an annual cycle.
  </Card>
  <Card title="Encryption in Transit" icon="lock">
    All data transmitted between your browser or API clients and LegFi KM is encrypted using **TLS 1.2 or higher**. Older protocol versions are disabled. LegFi KM enforces HTTP Strict Transport Security (HSTS) and uses certificates from a trusted Certificate Authority with automatic renewal.
  </Card>
  <Card title="API Token Security" icon="key">
    API tokens are stored in a non-reversible hashed form — LegFi KM never retains or logs a token's plaintext value after the moment of creation. If a token is compromised, revoke it immediately from **Settings → Security → API Tokens** — revocation takes effect within seconds.
  </Card>
  <Card title="Password Security" icon="shield-halved">
    User passwords are stored using a secure, salted hashing algorithm. LegFi KM enforces a minimum password length of 12 characters and checks new passwords against a database of known-compromised credential sets to prevent the use of breached passwords. Admins can enforce additional password complexity requirements from **Settings → Security → Password Policy**.
  </Card>
</CardGroup>

## Access Controls

LegFi KM enforces multiple layers of access control to ensure that only authorized users can view or modify sensitive knowledge content.

<Accordion title="Role-Based Access Control (RBAC)">
  Every user in LegFi KM is assigned one of four roles: Viewer, Contributor, Reviewer, or Admin. Each role carries a defined set of permissions that govern which actions the user can take across the entire workspace. Permissions are enforced on the server side on every request — client-side interface restrictions are never the sole security boundary.

  For a detailed breakdown of each role's permissions, see [User Management](/admin/user-management).
</Accordion>

<Accordion title="Entry-Level Permissions">
  In addition to workspace-wide roles, individual knowledge entries can be restricted to specific teams or users. An entry marked as **Restricted** is visible only to the users or teams explicitly listed in its access list, regardless of their workspace role. This is useful for entries containing pre-publication regulatory analysis, draft legal opinions, or M&A-related content that should not be visible to the full workspace.

  Configure entry-level permissions from the **Permissions** tab in the entry editor, or set default permissions for an entire topic branch under **Settings → Topics → [Topic] → Default Permissions**.
</Accordion>

<Accordion title="Session Management">
  Authenticated sessions are short-lived and automatically expire after a configurable period of inactivity. Admins can configure the maximum session duration and enforce re-authentication after periods of inactivity from **Settings → Security → Session Policy**. All active sessions for a user are listed under their profile — Admins can terminate any session remotely from **Settings → Team → [User] → Active Sessions**.
</Accordion>

<Accordion title="Single Sign-On (SSO)">
  Enterprise customers can enforce SSO via SAML 2.0 or OIDC, ensuring that authentication is controlled by your organization's Identity Provider and subject to your existing MFA policies. When SSO is enabled in enforced mode, password-based login is disabled for all non-Admin accounts. See [User Management — Single Sign-On](/admin/user-management#single-sign-on-sso) for setup instructions.
</Accordion>

## Data Residency

By default, LegFi KM stores all customer data in the **United States**. Enterprise customers can select their preferred data region at account creation time, or contact LegFi KM support to arrange a migration to a different region.

<CardGroup cols={3}>
  <Card title="United States" icon="flag-usa">
    **US region** (Northern Virginia). Default region for all new accounts. Data does not leave this region unless you configure a secondary backup region as part of a custom Enterprise agreement.
  </Card>
  <Card title="European Union" icon="earth-europe">
    **EU region** (Ireland). Select this region to ensure your data remains within the European Economic Area, supporting GDPR data residency requirements. All backups and replicas remain within the EU.
  </Card>
  <Card title="Asia-Pacific" icon="earth-asia">
    **APAC region** (Singapore). Select this region for data residency in Southeast Asia. Suitable for organizations subject to MAS TRM guidelines or other APAC regulatory frameworks requiring local data storage.
  </Card>
</CardGroup>

<Warning>
  Data region selection is permanent at account creation for self-serve accounts. If you need to migrate an existing workspace to a different region, contact **support@legfikm.com** at least 10 business days in advance. Migrations require a scheduled maintenance window.
</Warning>

## Compliance Certifications

LegFi KM maintains the following compliance certifications and standards. Relevant documentation is available to Enterprise customers on request under NDA.

<Accordion title="SOC 2 Type II">
  LegFi KM is audited annually against the AICPA Trust Services Criteria by an independent third-party auditor. The SOC 2 Type II report covers the **Security**, **Availability**, and **Confidentiality** trust service categories. The report evaluates the design and operating effectiveness of LegFi KM's controls over a 12-month audit period.

  Enterprise customers may request a copy of the most recent SOC 2 Type II report by emailing **security@legfikm.com** from your registered Admin email address. The report is shared under a mutual NDA.
</Accordion>

<Accordion title="ISO 27001">
  LegFi KM's information security management system (ISMS) is certified to **ISO/IEC 27001:2022** by an accredited certification body. The certificate is renewed on a three-year cycle with annual surveillance audits. The scope of the certification covers the development, operation, and support of the LegFi KM SaaS platform.

  A copy of the current ISO 27001 certificate is available on request from **security@legfikm.com**.
</Accordion>

<Accordion title="GDPR">
  LegFi KM acts as a **data processor** on behalf of its customers, who are the data controllers for any personal data stored in their workspaces. LegFi KM's data processing practices comply with the General Data Protection Regulation (GDPR).

  A **Data Processing Agreement (DPA)** — incorporating the EU Standard Contractual Clauses (SCCs) for transfers outside the EEA — is available on request. Contact **legal@legfikm.com** to receive and execute a DPA for your organization.
</Accordion>

## Data Retention and Deletion

LegFi KM retains all workspace data — including entry content, version history, and audit logs — for the **life of your account**. After your subscription is cancelled or expires, data is retained in a read-only state for **90 days** to allow for export and transition. At the end of the 90-day grace period, all workspace data is permanently and irreversibly deleted within 30 days.

**Enterprise custom retention policies:** Enterprise customers can configure custom retention schedules to align with their own regulatory obligations — for example, retaining audit logs for 7 years to satisfy SEC Rule 17a-4, or automatically purging draft entries that were never published after 180 days. Configure retention policies under **Settings → Security → Data Retention** or work with your LegFi KM account manager to implement a policy that matches your jurisdiction's requirements.

<Tabs>
  <Tab title="Standard Retention">
    | Data Type | Retention Period |
    |---|---|
    | Published entries and metadata | Life of account + 90 days post-cancellation |
    | Version history | Life of account + 90 days post-cancellation |
    | Audit logs | Life of account + 90 days post-cancellation |
    | Deleted entries (soft-deleted) | 30 days, then permanently removed |
    | User data (deactivated users) | Life of account + 90 days post-cancellation |
    | API token records | Deleted within 24 hours of revocation |
  </Tab>
  <Tab title="Enterprise Custom Retention">
    Enterprise customers can define custom retention rules per data category. Rules are evaluated nightly and applied automatically. Example configurations include:

    - Retain all audit logs for **7 years** (SEC, FINRA, MiFID II compliance)
    - Automatically delete draft entries that have not been submitted for review within **180 days**
    - Purge version history older than **5 years** for entries in the **Archived** status
    - Retain deleted entries in a recoverable state for **90 days** before permanent deletion

    Contact your LegFi KM account manager or email **support@legfikm.com** to design and implement a custom retention policy for your workspace.
  </Tab>
</Tabs>

## Exporting Your Data

You own your data. At any time, you can export your complete workspace — all entries, topics, users, and audit logs — as a portable archive.

<Steps>
  <Step title="Initiate a Full Backup Export">
    Navigate to **Settings → Data Export** and click **Full Backup**. LegFi KM begins compiling the export immediately. Depending on the size of your workspace, this may take between a few minutes and up to an hour for very large workspaces.
  </Step>
  <Step title="Receive the Download Link">
    When the export is ready, LegFi KM sends an email to your Admin address with a secure download link. The link is valid for 48 hours. You can also check the status of in-progress or completed exports from the **Settings → Data Export → Export History** page.
  </Step>
  <Step title="Download and Verify the Archive">
    Download the ZIP archive. The archive contains the following:

    - **`entries/`** — all knowledge entries in both JSON (structured metadata) and Markdown (human-readable content) formats, organized by topic
    - **`topics/`** — your full topic taxonomy as a JSON file
    - **`users/`** — user roster with roles and status as a JSON file
    - **`audit_logs/`** — complete audit log as both JSON and CSV

    Each ZIP archive includes a `manifest.json` file listing every included file with its SHA-256 checksum so you can verify the archive's integrity.
  </Step>
</Steps>

<Tip>
  Schedule a full backup export at least monthly — or before any significant organizational change such as a plan upgrade or team restructuring — so you always have a recent, verified copy of your knowledge base outside of LegFi KM.
</Tip>

## Audit Logs

Every action taken within LegFi KM — entry creation, edit, publish, review decision, user invitation, permission change, SSO configuration update, and more — is recorded in a tamper-evident audit log. Audit logs are append-only: existing records cannot be modified or deleted by any user, including Admins.

Access the audit log from **Settings → Audit Log**. Filter by date range, user, action type, or affected resource. Click any audit log entry to see its full detail, including the before and after state for edit actions (a structured diff of changed fields).

Export the audit log in CSV or JSON format for a selected date range using the **Export** button at the top of the Audit Log page. This export is separate from the full workspace backup and can be run independently on demand.

<Info>
  The audit log is a read-only resource for all users, including Admins. It cannot be cleared, modified, or selectively deleted through the LegFi KM interface or API. If you have a legal or regulatory obligation to produce audit records, the export function is the appropriate mechanism for doing so.
</Info>
